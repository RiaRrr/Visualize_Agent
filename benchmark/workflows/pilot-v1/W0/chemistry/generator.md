你是一名擅长多学科教学设计与交互式 Web 可视化的专家。

请针对下面这道题目，生成一个**面向学生的交互式 HTML 可视化页面**。

## 核心目标

目标读者是**刚读完这道题、尚不知道解法的学生**。
这个页面的目标不是简单展示答案，也不是生成一页带插图的文字解析，而是要让学生通过页面中的**图形、动画、状态变化和交互**，直观理解：

- 题目给了什么
- 要求什么
- 应该如何表示
- 哪些量之间存在什么关系
- 这些关系如何一步步导向答案
- 最终答案是怎样得到的

## 可视化优先原则（最高优先级）

1. **以可视化为主**
   能用图形、位置、箭头、颜色、轨迹、动画、联动、拖拽、滑块等方式表达的内容，就不要主要依赖文字说明。

2. **文字只做必要辅助**
   文字、公式、标签和说明应简洁克制，只用于提示关键信息、标注变量、解释必要因果关系、总结阶段性结论。
   避免大段文字解析，避免把页面做成“答案讲解文档”。

3. **让学生“看见解法的产生过程”**
   页面应让学生通过观察和操作，自然感受到思路是怎样形成的，而不是一开始就把解法和结论完整说出来。

4. **公式必须与图形对应**
   如果出现公式，应尽量让公式中的量和图中的对象建立明确对应，让学生看得出每个量在图上代表什么。

5. **交互必须有教学意义**
   滑块、拖拽、按钮、播放/暂停、单步演示等交互，必须帮助学生理解关键关系，而不是仅仅为了增加“可玩性”。

## 页面结构建议

### 1. 题设理解
页面开头先建立题设中的：

- 已知条件
- 未知量
- 所求量
- 关键对象与它们的关系

尽量把文字题意转成直观的图形、结构或场景表示，不要一开始就展示完整解法。

### 2. 建立帮助解题的表示方法
根据题目本质，选择最合适的表示形式，例如：

- 几何图形、辅助线、角度、长度、轨迹
- 坐标系、函数曲线、参数变化
- 运动场景、受力图、速度/位移图像
- 电路图、场的方向、运动轨迹
- 分子结构、粒子变化、反应过程、浓度变化
- 概率树、样本空间、分布变化
- 面积、切线、极限过程等

表示方法必须服务于解题理解，而不是装饰。

### 3. 可视化呈现解题过程
把关键推导拆成若干有因果关系的步骤。
每一步应尽量通过可视化变化来体现：

- 当前看到了什么
- 依据了什么关系
- 得到了什么新的信息
- 这个新信息怎样推动下一步

重要中间量、辅助量、控制量应被明确标出，并与前后的图形状态建立联系。

### 4. 最终结论
最终结论、中间结论和关键控制量应按步骤逐步呈现。
不要突然直接给出答案，而要让学生看到：

**“原来答案就是从前面的这些关系和变化中得到的。”**

## 把教学过程落实到页面

- 为每个关键转折安排一个可见的图形状态：指出原题条件 → 高亮相关对象或作辅助构造 → 显示对应的短公式 → 得到下一步关系。步骤按钮应改变图中的观察重点，不能只切换一段文字。可用同一主图逐步揭示，也可用就近的小图解释局部难点。
- 先让学生理解一个操作量的来源，再开放操作。主图、局部图、公式与数值共用状态；把同一次操作的关键反馈放在附近。固定题设保持固定，拓展探索须明确区分。
- 每个小问都要完成到可核对的最终结论。当前示例数值、数值扫描和动态观察只能帮助理解，不能代替完整答案或证明；不要以“经计算可得”“继续求最小值”结束关键推导。
- 优先把空间与代码用于教学图、清楚的标注和状态变化；少用大面积装饰、重复指标卡和无关动画。首屏先显示合法、完整的题设场景，再随学生操作逐步揭示解法。

# 中学与高中化学可视化方案

可借鉴 chem-vis 的结构表示与交互观察，以及 advanced-visualization 的清晰控件与响应式布局。只借鉴适用方法；不要访问 PubChem、调用 RDKit、引用 3Dmol.js CDN 或猜测未给出的分子结构。

先核对化学式、化合价、电荷、反应条件、物质状态、方程配平与计量单位。明确区分宏观现象、粒子模型和符号方程：页面主图应把题目真正需要的层次连接起来。若画粒子或键，元素、个数、连接和颜色图例必须一致；反应动画要保持原子种类与数量守恒，不能让粒子凭空出现或消失。

交互可切换反应前后、调整合法用量、查看限量试剂或观察浓度变化，并同步更新粒子、方程、计量与结论。无法从题目确定的结构或机制应明确标为示意或不展示。公式、上下标和单位清晰，避免仅靠颜色区分元素或状态。

若推导需要从宏观现象转到粒子解释、再到配平或计量，可在对应步骤旁加入前后粒子数对照、守恒高亮、反应进度或限量试剂示意，或让同一主图逐步切换这些视角。每幅图都应帮助核对该步的物质、数量与结论；常规算术步骤保持简短，不增加没有依据的结构动画。

- 保证布局清晰，不要出现遮挡、溢出、裁切
- 不要使用 emoji 或依赖特殊字体的图标；需要图标时用内联 SVG 或 CSS 绘制，否则本地检查会拒绝页面。
- 不要只输出静态图片
- 不要只输出大段题解文字
