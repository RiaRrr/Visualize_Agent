# 小型数理化可视化 Benchmark

## 当前入口与状态
- 标注与题目浏览：http://localhost:8002/benchmark 。为保留原 8001 服务，新建独立本地服务；原工作台顶部有入口。
- 新版主应用也挂载 `/benchmark` 路由，下次正常重启 8001 后可同端口访问。
- 36 道候选题：数学、物理、化学各 12；每科开发 6、留出 6。题干、公式资源、参考答案和解析本地保存。
- 当前版本 `v1-candidate`，不是已经全面审定的 gold benchmark。所有入选理由、主题缺口与检查状态均记录。
- 第一批只运行三个开发题，每题 W0/W1/W2 三个方案，目标 9 份匿名页面。其余开发题与留出测试集不自动运行。
- 所有 workflow 生成、规划（后续接入）、流程内审核与返修使用 DeepSeek。当前统一用 GPT-5.6-sol 独立评分，评分不进入生成链路；人工校准与双评委对比按用户要求暂停。

## 目录
`math/`、`physics/`、`chemistry/`：每题一个目录，包含 question.json、source.json、stem.html、input.png、assets/、reference/。
`manifest.json`：题目来源、版本、开发/留出划分、题图哈希与入选理由。
`coverage.json`：全题池的本地知识点频率、入选主题、相似文本候选和覆盖缺口。
`workflows/`：历史方案登记与首批逐学科的配置、Prompt 快照。
`runs/artifacts/`：独立数据库与每次运行的逐轮 HTML、审核、请求、用量、截图；不写入原 data_v2 历史。
`evaluation/samples.json`：匿名样本到实际 HTML 的映射与选择规则，HTTP 标注接口不暴露模型、方案或内部评分。
`evaluation/human/<rater>/`：人工评分与每次修改历史，不允许模型代填。
`人工评分/`：从 data_v2 归档的真实人工评分页面、来源元数据和独立参考解；保留 data_v2 原件以维持历史链接。此组标记 historical_human，与新题分开统计。
`evaluation/judges/<judge>/<version>/`：独立模型原始响应和结构化评分，按 Prompt 版本保存。
`reports/`：对比结果；只有完成人工评分的样本才在前端展示模型分。

## 选题口径
数学题池 1719 道、物理 69 道、化学 87 道。没有按学科题量比例抽样，避免数学占据样本。
选题采用明确主题名额，结合题库频率、题型和可视化方式。不是概率随机抽样，也不把本地频率称为全国考试频率。
物理波动主题缺失；光学和热学样本很少。化学原子结构、有机合成等覆盖有限。详见 coverage.json。
文本相似度是去重辅助手段，不能证明不存在语义近似；版本冻结前仍需人工复核题族与答案。

## 运行与恢复
```bash
.venv/bin/python -m scripts.prepare_benchmark
.venv/bin/uvicorn app.benchmark:standalone --host 127.0.0.1 --port 8002
.venv/bin/python -m scripts.run_benchmark --concurrency 2
```
准备题库只下载题目所需资源并本地渲染，无模型请求。生成脚本会产生付费 DeepSeek 请求；重复运行复用 jobs.json 与已保存轮次，恢复未完成任务。不要同时启动两个生成脚本进程。
模型连接失败也保留记录，无 usage 时费用未知。不得把失败后没有产物的任务伪造为模型页面。
W0 单轮；首批 W1/W2 固定三轮用于校准界面。每轮完整保存，最终候选由流程内部最高综合分选出，同分选后轮；独立 judge 不参与选择。W1 与 W2 推理均为 high，避免把推理强度变化混入修订方式比较。正式测试轮数须另行冻结。

## 人工评分
每个评分者使用自己的编号（字母、数字、下划线或短横线）。五维 1–5、综合 0–5；空白是未评分。可保存草稿、跳过或提交。提交须完整填写。
评分绑定 HTML 哈希、rubric 版本与 revision；多标签页冲突返回 409，不静默覆盖。修改保留历史。
检查原题、参考答案、实际交互、关键中间步骤和边界。参考有疑问时打标签，该样本不进入 judge 排名。
首批 9 份仅用于校准。后续扩展至 12 道开发题×3 份 HTML=36 份，按题目拆为 18 份校准、18 份验证；同题各轮不可跨组。验证组不用于修改 judge Prompt。

## 独立模型评价
```bash
.venv/bin/python -m scripts.evaluate_benchmark --score-only --set calibration --judges gpt_56
```
当前仅启用 GPT-5.6-sol。score-only 模式不要求先填人工分，也不代填人工分；结果显示于页面“GPT 评分”。重复运行会跳过证据哈希一致的已完成评价，不重复付费。
已有人工分原文保存于 `人工评分/样本/<id>/human_original.json`；归档脚本为 `scripts.import_human_benchmark`。不把模型分当人工分，不给 judge 看人工分或原 reviewer 的评语。
首批历史页面来自两道原始上传题。未在给定题库中找到精确题源，按用户要求独立求解，解析和边界检查在对应题目的 `reference/解析.md`，标明“本次独立推导，待人工复核”。参考解不从候选 HTML 提取。
judge 只接收原题、参考图片、完整 HTML 与操作证据，绝不接收人工分数。失败单独保存，未返回 usage 的调用费用未知。
参考答案原文不是人工真值；需要结合 checks.json 和人工核查。证据不足可给 null，不能编造已验证的交互。
人工校准代码保留：不带 score-only 时，仍要求已有人工评分，才能计算 MAE、±1 分比例、同题排序一致率和严重错误漏判。当前不继续运行该实验，已有部分比较结果保留，不据此宣布最佳评委。
不把同一题多个 HTML 当成独立题数。独立 judge 评分与原 reviewer 分数独立保存。

## 成本与复现
保存模型标识、网关、输入图片哈希、实际请求 Prompt、原始响应、推理设置、输出上限、每次 API 用量与耗时。未知单价与缺失 usage 不当作 0。
资源与运行产物保留在本地，git 跟踪元数据、脚本和 Prompt；不把大批公式资源、题库原文或人工标注上传到远程仓库。
网关 DNS 间歇失败时，可显式传 `--gateway-ip <实际解析的内部地址>` 给生成或评价脚本。仅覆盖本进程对原网关域名的解析，不修改系统网络；不要使用猜测或过期地址。
