# 独立评价 v2：逐维度调用
每个页面固定发起六个独立请求：一致性、正确性、页面效果、交互效果、教学效果、综合分。每次都收到同一份原题、参考材料、页面截图、操作记录和完整 HTML。五维分别使用自己的评分标准；综合分独立判断，不看五维结果、不机械平均。所有请求均不提供生成模型、workflow 或人工评分。
教学效果代入具备高中基础、刚读完题但不会做题的学生，沿实际阅读顺序判断能否循序渐进理解解法，指出理解障碍；不能以评审者知道的解法或学生看不到的源码替页面补讲解。专项要求在 `app/prompts/reviewer_teaching.md`，生成流程内的 reviewer 也会加载这份要求。
`dimensions.json` 保存各维度标准；`judge_prompt.md` 是共同评估约束，`dimension_prompt.md` 与 `overall_prompt.md` 分别约定输出格式。提示词及调用协议共同决定评分版本。历史评分和冻结的 pilot-v1 工作流不改写。生成流程内的 reviewer 更新教学标准，仍保持原有一次联合审核；这里六次隔离调用用于 benchmark 独立 judge，以免改变已经冻结的生成实验。
每个样本的汇总记录保持旧格式兼容页面，并新增 `evaluation_mode`、`calls`、`api_call_count`、逐项用量和耗时。同名目录保存六份提示词、每次尝试的原始回复和 JSON。某维度失败不会产生完整评分；重跑只补失败项。计费统计包含失败尝试；API 未返回的用量为未知，`known_total_tokens` 仅是已知小计。
六次调用会重复传入图片和源码，通常比原来一次联合评分更贵；实际用量以 API 返回为准。同一样本六项顺序执行，不增加网关并发上限。此改动不自动启动收费调用，也不会重新生成 HTML。
仅重评一个样本（在仓库根目录执行）：
```bash
.venv/bin/python -m scripts.evaluate_benchmark --score-only --judges gpt_56 --samples B50DFB016 --concurrency 1
```
新旧版本同时保留，应按版本比较，不混成同一套评分结果。尚未用新标准重新调用模型的页面仍显示历史分数。
