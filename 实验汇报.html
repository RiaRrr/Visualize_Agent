从题图到可交互解题页面

同题比较直接生成与先规划后生成。每个案例保存逐轮 HTML、截图、模型审核、token 与用时，方便人工复核。

25 个任务66 轮 HTML3 道题更新：2026-10-19 12:20

架构与实验路径

浏览器上传 / 历史 / 人工评分→FastAPI 任务接口→Pipeline 编排→统一 ModelClient→Chrome 渲染与交互检查→SQLite 索引 + data_v2 文件

共用前处理

  1. 上传题图并保存带时间戳的原图。
  2. 多模态模型分流学科；本次数学实验共用同一份题目 OCR 与图形描述。
  3. 加载固定的通用可视化要求、数学经验和输出格式要求。

直接生成

  1. OCR 题意送给文本生成模型，生成完整 HTML。
  2. 本地检查源码，浏览器渲染并试用可见交互。
  3. 题意、截图描述和源码送审核模型评分并提修改意见；固定三轮。

规划后生成

  1. 同一生成模型先输出公开的解题与可视化规划 JSON。
  2. 独立文本模型核对规划，最多三次尝试；未通过则停止。
  3. 原版生成 Prompt 加核对过的规划，再进入相同三轮 HTML 流程。

存档与查看

  1. 每轮 HTML、截图、模型审核、人工评分和 API 阶段记录存入 data_v2。
  2. 历史页显示模型、配置、轮次及最佳轮；本页链接到所有轮次。
  3. OCR 共用，不重复计入各任务的 token 与 API 用时。
评价口径：自动审核分可能误判数学结论或忽略页面问题；10.17 双曲线规划版虽被自动判为通过，最终值域仍漏掉内部不可取的 2 与 30/19。下面“效果观察”结合了人工核对。V2、V4.1 与 10.17 的规划提示比 V1 更具体，不能把跨批次差异只归因于模型。10.17 型号使用项目中的另一把网关密钥；两把密钥的可见模型目录不同。
