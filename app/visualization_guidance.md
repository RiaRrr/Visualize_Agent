# 数学题教学可视化生成指导

本文件是提供给生成模型的项目指导，汇集以下五项 skill 中适合“题目图片 → 离线单文件 HTML”的规则：

- interactive-whiteboard: https://github.com/xuyannan0321/math-ai-edu-site/blob/main/.agents/skills/interactive-whiteboard/SKILL.md
- math-teacher: https://github.com/jamesrochabrun/skills/blob/main/skills/math-teacher/SKILL.md
- html-report: https://github.com/chang-xinhai/agent-html-report-skill/blob/main/.claude/skills/html-report/SKILL.md
- visualize-data: https://github.com/openai/plugins/blob/main/plugins/data-analytics/skills/visualize-data/SKILL.md
- math-skills: https://github.com/panpanc/math-skills

项目要求优先：只输出一个可离线打开的 HTML 文件；不得引用 CDN、外部脚本、字体、图片或其他网络资源；不得发布、提交代码、调用外部工具或要求额外文件。以下规则是设计指导，不是让你执行 skill 中的脚本或工作流。

## 先理解题目，再设计画面

1. 准确抄取原题的条件、目标和限制，特别留意系数、严格不等号、点的位置、退化情形。先在内部完成推导与边界检查，再制作页面；不要把思考过程或未核实的结论写给用户。
2. 选出一个读者最需要直观看到的数学关系作为主图，再找出后续推导中最难凭文字理解的转折。可在对应步骤旁画局部图，也可让主图高亮、切换状态或显示逐步变化，使条件、图中对象、公式和下一步结论互相指向。无需给每一步都配图；若主图已足以解释该步，要在步骤处明确指出读者应观察的对象。
3. 按题目内容组织清晰的阅读顺序，不固定为“主图后面接大段推导”。把关键图解放在需要它的推导附近，较简单的代数步骤保持简洁。公式用内联 HTML、SVG 或 MathML 表示；保证字号、对比度、留白和手机阅读体验。图上直接标注关键点、量和颜色含义，避免装饰压过证据。

## 数学图形必须忠实

4. 图中坐标、点位、线段、角度、面积和曲线必须与同一组合法参数一致；不要画不满足题意的“示意参数”，也不要让图与公式各用一套数值。区分精确图形与仅表达结构的示意图。
5. 对抛物线等解析曲线，使用与函数一致的连续 SVG 二次/三次贝塞尔路径（`Q`/`C`）或 Canvas 曲线 API；若必须采样，采样密度应在实际显示尺寸下不可见折角。不要用少量 `L` 直线拼接出明显分段的曲线。显示顶点、交点等标记时，应从同一数学表达式计算其坐标。
   对函数 `y=f(x)` 的二次曲线，在数据坐标区间 `[x0,x1]` 上用单段 `Q` 时，控制点横坐标必须是 `(x0+x1)/2`，纵坐标是 `2*f((x0+x1)/2) - (f(x0)+f(x1))/2`，然后用与端点相同的坐标映射转换为屏幕坐标。切勿默认控制点横坐标为 0：当左右端点不对称时，这会使曲线偏离函数和标记点。对 `y=x²/8`，控制点可化为 `((x0+x1)/2, x0*x1/8)`。

## 交互服务于理解

6. 适合参数探索时提供滑块、步骤切换或播放/暂停。控件放在图附近或图下方，手机可触控，显示当前值、合法区间和必要的重置操作。非法参数要限制或明确提示。
7. 参数变化时，同步更新相关图形、点位、填色、标签、公式中的数值和最终结果；不能只改变一个数字而图仍是旧状态。关键结论在不操作时也应可读。步骤切换应让读者看见本步新增的线、点、面积、约束或比较，而不是仅隐藏文字；必要时用局部放大图解释主图难以看清的关系。
8. 动画仅用于揭示数学变化；频繁重绘可用 `requestAnimationFrame`。保持页面滚动和键盘操作可用，不用积分、排行榜等与这道题无关的游戏元素。

完成前自查：题意和边界是否正确？图形是否与公式及参数一致？曲线是否平滑？交互是否真的改变可视化？离线打开及手机布局是否可用？
