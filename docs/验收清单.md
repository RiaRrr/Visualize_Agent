## 手工验收步骤（无需API）
1. 按根README克隆、创建虚拟环境、安装 `requirements-lock.txt`。
2. 在仓库根目录运行 `python -m scripts.check_benchmark`，应报告36道题、12份样本、21轮HTML且 errors 为空。
3. 运行 `python -m uvicorn app.benchmark:standalone --host 127.0.0.1 --port 8002`，打开 `http://127.0.0.1:8002/benchmark`。
4. “题目浏览”中检查数理化题图均可打开；当前候选题共36道。
5. “GPT评分”中应有9份旧评分；点击数学W1，核对选中第2/3轮；模型评分不能当成人工评分。
6. 打开 `?sample=B50DFB016`，确认原题、参考解、HTML、截图均显示；真实操作页面的滑块/按钮。模型产物中的缺陷是评测对象，未被手工修成“标准结果”。
7. 评分者为 `primary` 时能看到已有分数；换成自己的编号后填写评分、保存、刷新确认保留。不要覆盖原评分者做验收。
8. 查看 `benchmark/reports/分享汇总.csv`，核对人工五维/综合分、选中轮次、相对HTML路径、token与价格。
9. 直接在本地浏览器打开汇总表对应的单个生成HTML；它不依赖本地API服务。工作台首页 `web/benchmark.html` 则必须通过服务打开。
## 自动检查
```bash
python -m scripts.check_benchmark
python -m pytest -q
node --test tests/test_cost_display.cjs
```
前两条分别检查发布数据完整性与Python功能；Node仅用于前端费用逻辑测试，不是运行依赖。测试不调用真实模型。
## 明确的边界
- 36道题是候选集，不是所有参考解都已人工审定；只有3道开发题完成本批workflow，留出集没有用于调参。
- 新的6次独立评分未运行，不能声称其优于旧judge。本版只验证调用隔离、结果格式、重试与记录等工程行为。
- 普通生成流程内的reviewer同步采用新的教学标准，仍是一次联合审核；逐维独立call用于benchmark外部judge。冻结的历史任务沿用自己的Prompt快照。
- 旧报告保留当时的探索记录和本机历史路径，当前可直接打开的完整数据范围以benchmark索引和README为准。
- 模型可用性取决于网关账号。无Key的验收覆盖浏览/标注与本地测试，不包含真实收费生成或新评分。
